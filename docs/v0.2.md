# v0.2: FDE workspace UI — acceptance review

v0.2 is complete when an FDE can model and inspect one workflow in the UI and
then use the same definitions in the v0.1 operational loop, with inspectable
evidence for each stage. The interaction contract is
[authoring-flow.md](authoring-flow.md); the stack decision is
[ADR 0001](adr/0001-web-framework.md); the repeatable procedure is
[v0.2-walkthrough.md](v0.2-walkthrough.md).

## Acceptance checklist

- [x] The FDE can complete the job-invoicing authoring flow without hand-editing supported fields in YAML. (Structured editors for all four definitions — domain graph + forms, mapping form, evaluation form, agent-task form — mutate the draft bundle through the CST-preserving YAML API; unexposed fields, comments, and ordering round-trip. See [web.md](web.md) and [v0.2-walkthrough.md](v0.2-walkthrough.md).)
- [x] Domain visualization and mapping preview match the persisted definitions and shared-core outputs. (The graph/list render the same draft YAML the forms edit; preview parity with the core is pinned field-for-field minus volatile `observed_at` — `test_api.py::test_preview_parity_with_core`, `test_preview_uses_draft_not_disk`.)
- [x] UI-saved definitions pass CLI validation and can be used by the operational loop established in #11. (`apps/api/tests/test_authoring_loop.py::test_saved_bundle_runs_operational_loop` — API open → edit all four definitions → validate → preview → save → `ontology check`/`ingest`/`project`/`diagnose`/`decide`/`execute`/`evaluate` on the saved workspace.)
- [x] Invalid definitions, preview errors, stale saves, failed saves, and unsaved drafts behave as documented. (`test_save_invalid_draft_writes_nothing`, `test_save_conflict_on_external_change`, preview diagnostic tests in `test_api.py`; stale-result and save-conflict behavior in `apps/web/app/test/workspace-store.test.ts`.)
- [x] The UI does not bypass human approval or change deterministic outcome semantics. (The API contract exposes only `open`, `validate_draft`, `save`, `preview_draft` — asserted by `test_contract_exposes_no_action_authority`. Validation and save go through the shared core; proposals/decisions/write-back exist only in the operational loop.)
- [x] A clean install/build and repeatable test/walkthrough procedure are documented; incomplete surfaces are not described as implemented. ([v0.2-walkthrough.md](v0.2-walkthrough.md); CI runs `pip install -e` + `pytest` and `npm ci` + typecheck + test + build from clean checkouts.)

## Known limitations

- **Single-user local model.** The API binds loopback, restricts access to
  configured `--root` directories, and carries no authentication — it is a
  local FDE tool, not a multi-user service. Concurrent writers are detected
  by the base-digest check, not coordinated.
- **Projection authoring is not exposed.** Domain `projections:` can be
  renamed/removed/re-subjected but not created in the UI — an unassigned gap
  in [authoring-flow.md](authoring-flow.md#gaps-and-unassigned-requirements).
- **No workspace creation or switching UI.** The flow assumes opening an
  existing workspace inside a configured root; enumerating multiple
  workspaces is unassigned scope.
- **Browser drafts do not persist across restarts.** Draft state lives in
  browser memory; restoring drafts after a restart is unspecified.
- **No browser-automation e2e.** The UI→API→YAML→CLI chain is covered by the
  API-level end-to-end test plus component/store tests; there is no scripted
  browser run in v0.2.
- **No write-back from the UI by design.** Execution receipts remain the CLI
  CSV adapter; the authoring surface has no approval or action endpoints
  (see the save contract in [authoring-flow.md](authoring-flow.md#save-contract)).

## Release gate

Same discipline as v0.1: repository stays private, no deployment or
publication is performed by this workflow, and no real-world outcome is
claimed from synthetic fixtures. A second model-selection benchmark was
explicitly not run — the UI changes no model-facing semantics, and the
recorded selection in [ADR 0002](adr/0002-default-diagnosis-model.md)
(status: Pending evidence, see [v0.1.md](v0.1.md#remaining-limitations-at-this-checkpoint))
still applies to the diagnosis step the authoring flow feeds into.
